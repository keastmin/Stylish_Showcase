# Basic Attack Studio / Dodge Attack Studio

기본 공격 1–4단은 `Tools > Character > Player > Basic Attack Studio`, 일반 회피 공격은 `Tools > Character > Player > Dodge Attack Studio`에서 편집한다. Q/E와 같은 헤더, 단계 선택 띠, 재생 도구, 마커 시간축, 상세 탭과 저장 영역을 사용한다.

일반 회피 공격은 실제 게임의 `PlayerRunAttackState` / `RunAttackTimeline`이다. 앞 회피 중 공격 입력과 뒤 회피의 초기 공격 입력이 이 동작으로 연결된다. 달리기 중 공격도 같은 동작을 사용하므로 변경 사항을 공유한다. 뒤 회피의 다른 행동 허용 구간 이후 공격은 기존 규칙에 따라 기본 공격 1단으로 연결된다.

완벽 회피 성공 후의 반격은 별도 `DodgeAttackStart`, `DodgeAttackLoop`, `DodgeAttackEnd` 시퀀스이며 이 두 창의 편집 대상에 포함하지 않는다. 이 도구를 여는 데 데이터 변환이나 연결 설치 과정은 필요하지 않다.

## 사용 순서

1. 씬의 플레이어를 선택하고 창을 연다. `편집할 플레이어`와 상단 연결 정보를 확인한다.
2. 기본 공격 창에서는 편집할 1–4단을 선택한다. 각 단계는 독립된 Timeline과 Animator 상태다.
3. `Scene 미리보기`를 열어 재생, 시작으로 이동, 한 프레임 이동, 반복, 재생 위치 슬라이더로 동작을 살펴본다. `관찰 배속`은 관찰 속도만 바꾼다.
4. 시간축의 마름모를 선택하거나 드래그해 실제 타격·행동 시각을 조절한다. 초와 해당 Timeline의 프레임 단위로 편집하며 프레임 스냅을 켤 수 있다.
5. 상세 탭에서 피해, 히트박스, 원본 모션, 실제 배속, 콤보 입력 신호, 이펙트를 조절한다. `마커로 이동`하면 해당 타격 프레임의 범위와 핸들을 확인할 수 있다.
6. `저장` 후 Play Mode에서 실제 입력 연결, 적 추적, 벽 충돌과 콤보를 확인한다. 상단 단계 선택과 미리보기는 편집 대상 하나를 재생하며 전체 4단 콤보를 자동으로 이어 실행하지 않는다.

## 편집 탭

| 탭 | 조절 항목 |
| --- | --- |
| 타격 · 범위 | 타격 시각, 타격 복제·삭제, 피해량, 경직 단계, 히트스톱 프레임·대상, 피격 레이어, Trigger 판정, 명중당 게이지, 실제 히트박스 |
| 클립 · 타이밍 | Animator 원본 애니메이션과 실제 공격 배속, 콤보 입력 허용·차단, 다른 행동 허용·종료 등 실제 Signal 시각 |
| 연출 | Control/Audio/Opacity 클립의 구간·배속·연결, 이펙트 오브젝트 배치, 트랙 사용 여부 |
| 연결 · 실행 | 실제 플레이어, Director, 공유 Timeline, Animator 상태, 신호 연결과 게임 실행 규칙 |

히트박스는 Box/Sphere/Capsule의 중심·크기·반경·축과 로컬 위치·회전을 숫자로 편집한다. Scene에서는 중심 이동·회전 핸들을 사용하며 Box 크기와 Sphere 반경도 핸들로 조절한다. 선택한 사용 중인 타격의 해당 프레임에서만 범위와 핸들을 표시한다. Capsule의 크기·높이는 숫자 입력으로 조절한다.

## 타격과 행동 시각

모든 마커 시각은 **선택한 공격 Timeline 시작부터의 초**다. 연결된 native `SignalEmitter → SignalReceiver → PlayerAttackInstanceContainer` 콜백을 그대로 편집하므로, 마커 순서나 이름을 바꾸어도 피해 필드 연결이 바뀌지 않는다.

`현재 시각에 타격 복제`는 원래 SignalAsset과 콜백을 공유하는 마커를 하나 추가한다. 같은 피해 필드에 연결된 마커는 피해량과 범위도 공유한다. 기본 공격의 일부 콜백은 해당 공격 중 이미 맞힌 대상을 기억하고, 다른 콜백은 반복 타격을 허용한다. 따라서 마커 복제가 언제나 추가 피해를 뜻하지는 않는다. 이 기존 동작은 변경하지 않는다. 마커 삭제는 해당 마커만 없애며 공용 Receiver 콜백을 삭제하지 않는다.

트랙 사용 설정은 그 트랙의 모든 신호 또는 연출 클립에 적용된다. 콤보·종료 신호를 사용하는 트랙을 끄거나 종료 시각 이후로 옮길 때는 실제 게임의 상태 전환도 함께 확인한다. 타격 하나의 사용 여부를 독립적으로 전환하는 설정은 없으며 선택 마커 삭제와 Undo를 사용할 수 있다.

현재 기본 데이터의 타격 수는 기본 공격 1–4단이 각각 **1 / 1 / 2 / 3회**, 일반 회피·달리기 공격이 **2회**다. 툴 추가 과정에서는 기존 타격 시각과 피해량을 변경하지 않는다.

## 원본 애니메이션과 배속

기존 공격 Timeline의 애니메이션 트랙은 음소거된 참조용이며 실제 자세는 Animator가 재생한다. `원본 애니메이션`과 `실제 공격 배속`을 수정하면 실제 Animator 상태의 motion/speed와 음소거된 Timeline 참조 클립을 함께 갱신한다. 참조 클립의 길이는 원본 길이 ÷ 배속으로 맞추고 음소거를 유지한다.

타격·행동 신호와 이펙트의 초 단위 시각은 자동으로 늘이거나 줄이지 않는다. 모션이나 배속을 바꾼 뒤 마커와 연출 시각을 함께 맞춘다. 기본 공격의 기존 자동 종료 조건은 애니메이션 정규화 시간 **92%**이며 창에는 계산한 기준 시간을 읽기 전용으로 표시한다. 일반 회피 공격은 기존 행동 허용 및 애니메이션 종료 신호를 사용한다.

원본 Animator 상태가 하나의 AnimationClip이고 일치하는 음소거 참조 클립을 하나로 확인할 수 있을 때만 모션 편집을 허용한다. Override Controller, Blend Tree, 배속·시간·오프셋 파라미터 제어 또는 0이 아닌 참조 시작/Clip In은 해당 연결을 확인하라는 설명을 표시한다. 이 경우 원래 Animator 설정을 자동으로 지우거나 변환하지 않는다.

## 미리보기와 저장

Scene 미리보기는 독립된 표시용 모델과 파티클을 만든다. 작성된 플레이어 Animator나 실제 Timeline을 평가하지 않으며 피해·행동 Signal과 애니메이션 이벤트를 실행하지 않는다. 사운드도 실행하지 않는다. 실제 적 추적, 충돌, 상태 전환은 Play Mode에서 확인한다.

미리보기 닫기, 단계·플레이어 변경, Undo/Redo에 따른 재구성, 스크립트 재컴파일, Play Mode 전환, 저장 시 임시 모델과 그래프를 정리한다. Play Mode에서는 편집이 읽기 전용이다.

Timeline의 마커·클립과 Animator 상태는 **공유 에셋**이므로 같은 에셋을 사용하는 다른 플레이어에도 영향을 준다. 피해 필드, 히트박스와 이펙트 오브젝트 배치는 선택한 씬/프리팹의 설정이다. 다른 씬에 같은 변경을 적용하려면 기존 Unity 프리팹 오버라이드 작업을 사용한다. `저장`은 먼저 미리보기를 종료하고 편집한 에셋과 관련 씬을 저장한다.

## 검증 실행

- `Tools > Character > Player > Validate Attack Studios Authoring`: 프리팹의 5개 실제 연결과 기본 타격 수, 격리된 native Signal 이동·복제·삭제 및 Undo/Redo, Animator/참조 클립 동기화, 지원하지 않는 파라미터 제어 보존을 검증한다.
- `Tools > Character > Player > Validate Attack Studios Preview`: 5개 동작의 독립 모델, 타격 시점의 히트박스 연결, 이펙트 구간, 배속과 자세·루트 위치, 역방향 스크럽, 미리보기 정리 및 원본 씬·에셋 보존을 검증한다.
- `Tools > Character > Player > Validate Attack Studios in Play Mode`: 현재 씬의 실제 기본 4단 콤보와 앞/뒤 일반 회피 중 공격 입력을 실행한다. 콤보 입력 창, 11회 총 타격, 복합 콜라이더 중복 방지, 실제 히트스톱, Timeline·루트 이동 정지/재개와 종료 처리를 검사하고 편집 모드로 돌아온다.
- 결과는 `Temp/PlayerAttackStudioAuthoringVerification.result`, `Temp/PlayerAttackStudioPreviewVerification.result`, `Temp/PlayerAttackStudioPlayVerification.result`에 기록한다. 검증 중 시험 데이터는 임시 객체 또는 Play Mode 인스턴스에만 적용하며 씬 에셋으로 저장하지 않는다.
- 세 검증은 전체 Player Timeline·Player 데이터·Animator Controller·플레이어 프리팹·두 게임 씬의 파일 해시를 비교한다. 완벽 회피/반격, E, Q의 작성 데이터를 포함한다. 런타임 검증은 완벽 회피 상태와 반격/E Director가 활성화되지 않는지도 확인한다.
